Two options: the full Compose stack (closest to production), or the two apps run
directly (fastest feedback loop).

## Option A — the Compose stack

```bash
git clone https://github.com/the-jk-labs/omicron.git
cd omicron
docker compose up -d --build
```

Everything is wired, including Postgres, Redis, and Caddy. Good for testing
upgrades, migrations, and anything involving the reverse proxy.

## Option B — run the apps directly

You need **Deno** (it runs the backend), **Node 24+**, **pnpm 12.11+**, and a
running **PostgreSQL** with `DATABASE_URL` set. A local `.env` is loaded too;
variables already set in the environment win.

```bash
# Once: the shared API contract both apps link
cd packages/contract && pnpm install

# Backend — http://localhost:8000
cd apps/backend
pnpm install
pnpm dev

# Frontend — http://localhost:5173
cd apps/frontend
pnpm install
pnpm dev
```

Migrations run automatically on backend startup, so an empty database is fine.

<Callout type="note" title="No Redis in this mode">
  Without `REDIS_URL`, the queue, Fedify's KV store, and the rate limiter all run in-process. That is fine for
  development; just remember that queued jobs vanish on restart. See [Delivery and queues](/federation/delivery/).
</Callout>

## Checks before you push

```bash
cd apps/backend  && pnpm fmt && pnpm check
cd apps/frontend && pnpm fmt && pnpm check
```

`pnpm check` runs [greenly](https://www.npmjs.com/package/greenly): in the
backend `tsc`, oxfmt, oxlint, and the unit tests; in the frontend oxfmt,
`svelte-check`, oxlint, and Vitest. Run `pnpm fmt` first so formatting never
fails the check.

<Callout type="note" title="Install the contract package first">
Every app links `packages/contract`, the shared API schemas, so run
`pnpm install` in `packages/contract` once before checking any of them. Skip it
and the checks report a missing `zod/mini` or `@omicron/contract` rather than
anything you changed. See
[the API contract](/development/frontend/#api-types-and-the-backend-contract).

</Callout>

## Testing federation locally

Federation needs a publicly reachable HTTPS domain, which `localhost` is not. Two
workable approaches:

1. **A tunnel** (Cloudflare Tunnel, ngrok, tailscale funnel) pointed at your local
   stack, with `APP_DOMAIN` set to the tunnel hostname.
2. **A cheap VPS** running the Compose stack on a real subdomain — closest to
   reality, and worth it before any federation-touching change.

<Callout type="warning">
  Do not test federation against your production domain. Actor URIs are built from the domain, so experiments create
  real identities other servers will remember. Use a throwaway subdomain.
</Callout>

## Useful during development

```bash
curl localhost:8000/healthz
curl localhost:8000/version

# Email in console mode prints reset/verification links here:
docker compose logs -f backend
```

## Creating a migration

```bash
cd apps/backend
# edit src/db/schema.ts, then:
pnpm db:generate          # writes new SQL into ./drizzle — commit it
```

See [Database and migrations](/development/database/).

## Project layout

```
apps/backend/      Hono + Fedify + Drizzle (runs on Deno)
apps/frontend/     SvelteKit + Bits UI + Tailwind + Tiptap
apps/mobile/       Expo (React Native) app for Android and iOS
packages/contract/ zod/mini schemas for every API response
docker-compose.yml The whole stack
Caddyfile          Public entrypoint config
install.sh         The one-line installer
```
