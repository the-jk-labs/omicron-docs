An external system — Sanity, Contentful, a static-site build hook, a script —
can publish straight into your instance by POSTing a document to one endpoint.
The result is an ordinary post: it appears in your feeds, is searchable, and
federates to your remote followers exactly like something written in the editor.

The endpoint is **off by default**. It exists only once you set a secret.

## Enabling it

Generate a secret and put it in your `.env` next to `docker-compose.yml`:

```bash
openssl rand -hex 32
```

```ini
WEBHOOK_SECRET=<the generated value>
```

```bash
docker compose up -d
```

| Variable | Default | Purpose |
| --- | --- | --- |
| `WEBHOOK_SECRET` | *unset* | Enables the endpoint. Minimum 16 characters. |
| `WEBHOOK_AUTHOR` | oldest account | Username that ingested posts are published as. |
| `WEBHOOK_MAX_BODY_BYTES` | `512000` | Reject a request body larger than this. |
| `RL_WEBHOOK_MAX` | `30` | Requests / min per source IP. |

<Callout type="warning" title="The secret is a publishing credential">
Anyone holding it can publish, edit, and unpublish posts as the configured
author. Treat it like a password: send it only over HTTPS, store it in your
CMS's secret store rather than in a template, and rotate it by changing
`WEBHOOK_SECRET` and restarting.
</Callout>

A short or malformed `WEBHOOK_SECRET` stops the backend at boot with a
configuration error rather than starting with a weak one.

## The request

```
POST /api/webhooks/content
X-Webhook-Secret: <WEBHOOK_SECRET>
Content-Type: application/json
```

The secret may travel in either header — `X-Webhook-Secret: <token>` or
`Authorization: Bearer <token>` — whichever your CMS makes easier. It is
compared in constant time.

### Body

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `title` | string | yes | Up to 300 characters. |
| `body` | string | yes | Markdown. Rendered to sanitized HTML on write. |
| `description` | string | no | Up to 500 characters. Defaults to the first ~150 characters of the body. |
| `banner` | string | no | Absolute `http(s)` URL of a cover image, hosted by you. |
| `slug` | string | no | Stable key for this document. Defaults to a slug of the title. |
| `tags` | string[] | no | Up to 5 after normalisation. Omit to leave existing tags alone; `[]` clears them. |
| `language` | string | no | BCP-47 primary subtag, e.g. `en`, `tr`. Drives the reader's language filter. |
| `status` | string | no | `published` (default) or `draft`. |

## Re-sending is safe

The `slug` is stored on the post as its external key. Send the same slug again
and Omicron **updates that post** instead of publishing a second copy — so an
at-least-once webhook, a manual retry after a timeout, or a CMS republish all
converge on one post.

<Callout type="tip" title="Send a stable slug">
Without `slug`, the key is derived from the title, so renaming a document
publishes a **new** post rather than updating the old one. If your CMS has a
document id, send it as `slug` and retitling works correctly.
</Callout>

A title with no ASCII characters derives to an empty key; those documents must
send an explicit `slug` and are rejected with `400` otherwise.

## Responses

Success returns the post's id and the key it is stored under:

```json
{ "id": "9e962281-…", "slug": "eu-payments", "status": "published", "created": true }
```

| Status | Meaning |
| --- | --- |
| `201` | A new post was created. |
| `200` | An existing post with that slug was updated (`"created": false`). |
| `400` | Invalid payload. The message names the offending field. |
| `401` | Missing or wrong secret. |
| `409` | That slug belongs to a post this webhook does not own. |
| `413` | Body larger than `WEBHOOK_MAX_BODY_BYTES`. |
| `429` | Over `RL_WEBHOOK_MAX`. `Retry-After` says how long to wait. |
| `503` | No `WEBHOOK_SECRET` set, or no usable author account. |

Errors never echo the secret, and nothing logs it.

## Example

```bash
curl -X POST https://your-domain/api/webhooks/content \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: $WEBHOOK_SECRET" \
  -d '{
    "title": "Europe is ditching Visa and Mastercard",
    "body": "## The short version\n\nIt is a **huge** step.",
    "description": "Why the EU payments shift matters.",
    "banner": "https://cdn.example.com/covers/eu-payments.jpg",
    "slug": "eu-payments",
    "tags": ["fintech", "europe"],
    "language": "en"
  }'
```

Substitute your own instance's domain — this works on any Omicron instance, not
just one in particular. Point it at `http://localhost/api/webhooks/content` to
try it against a local stack.

## What happens to the content

**The Markdown is rendered on the way in, not on the way out.** Omicron stores
the sanitized HTML, the same as a post written in the editor. Every tag outside
the allowlist — `<script>`, event handler attributes, inline styles,
`javascript:` links — is dropped before anything is stored. This is why the
endpoint can accept content from a machine safely.

The practical consequence: what you send is what gets published, but exotic raw
HTML in your Markdown may not survive. Standard Markdown, tables, code fences,
images and links all do.

## What federates

A published post is delivered to your remote followers as a `Create(Article)`.
On top of the usual title, body, and tags:

| Field | Federates as | Seen by remote instances as |
| --- | --- | --- |
| `description` | Article `summary` | The preview line above a long-form link |
| `banner` | Article `image` | The link card's image |

Re-sending an already-published post delivers an `Update(Article)` so remote
copies refresh. Flipping a published post to `"status": "draft"` tombstones the
copies already delivered.

<Callout type="note" title="The banner is not shown on your own site yet">
`banner` is stored, returned by the API, and federated. The post page does not
render it yet, so today it is visible to other fediverse instances rather than
to readers on your instance.
</Callout>

## Limits and what this is not

- **No signature verification.** Authentication is the shared secret, not an
  HMAC of the payload. If your CMS signs its webhooks, that signature is not
  checked.
- **No scheduling.** A document is published when it arrives.
- **No deletes.** There is no webhook path that removes a post; set
  `"status": "draft"` to unpublish, or delete it from the UI.
- **One author.** Every ingested post is attributed to `WEBHOOK_AUTHOR`.
